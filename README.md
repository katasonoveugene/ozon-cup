# Решение задачи «Контроль качества»

В репозитории находятся код для запуска и обучения, готовая модель и
артефакты обучения итогового ансамбля из пяти компонентов.

Public: `0.7753636645`
Private: `0.8676432456`

## Описание метода

Модель принимает решение отдельно для каждой из двух категорий товаров и
объединяет пять дополняющих друг друга оценок:

1. TF-IDF по словам и символьным n-граммам объединённого текста карточки с
   повторённым названием, затем линейный SVM;
2. отдельные TF-IDF-признаки для названия и описания, затем линейный SVM;
3. линейный SVM со взвешиванием классов на нормализованных мультимодальных
   эмбеддингах;
4. SVM с RBF-ядром на тех же эмбеддингах;
5. локальная оценка по ближайшим соседям: среднее косинусное сходство с двумя
   ближайшими положительными примерами минус такое же среднее для отрицательных.

Мультимодальные эмбеддинги строятся моделью
`Qwen/Qwen3-VL-Embedding-2B`. На вход ей передаются
название, описание, категория и все изображения товара. Оценки каждого
компонента нормируются отдельно внутри каждой категории. Итоговая оценка
вычисляется по формуле:

```text
0.25 * z(sparse text)
+ 0.25 * z(separated text)
+ 1/6  * z(embedding linear)
+ 1/6  * z(embedding RBF)
+ 1/6  * z(top-two retrieval)
```

Для каждой категории используется свой порог, который переводит итоговую
оценку в метку 0 или 1.

Обучаемые компоненты были построены на пяти фолдах,
сформированных по группам источников и шаблонов. Связанные карточки всегда
попадают в один фолд, что предотвращает утечку между похожими товарами и
шаблонами.

По условию задачи каждая строка результата должна содержать пояснение длиной от 50 до 300 символов. Сначала ансамбль фиксирует класс
товара, после чего `Qwen/Qwen3.5-4B` формирует пояснение по названию, описанию и
категории. Генерация текста не участвует в классификации.

## Основные файлы

- `run.py` — точка входа для получения предсказаний. Скрипт проверяет входные
  данные, извлекает эмбеддинги, загружает обученный ансамбль, формирует пояснения
  и проверяет итоговый CSV.
- `quality_core/validated_blend.py` — расчёт пяти оценок, их калибровка отдельно
  для каждой категории, объединение и получение предсказания.
- `train_validated_blend.py` — воспроизведение итогового ансамбля по размеченным
  данным, заранее рассчитанным мультимодальным эмбеддингам и зафиксированному
  разбиению на группы и фолды.
- `artifacts/validated_blend.joblib` — обученные TF-IDF-векторизаторы, ансамбли
  SVM для каждой категории, параметры калибровки и эталонные эмбеддинги
  обучающей выборки.
- `outputs/mixed.npy` — точная матрица мультимодальных эмбеддингов, выровненная
  по строкам обучающей выборки и использованная для обучения итогового ансамбля.
- `outputs/source_template_stress_manifest_v2.npz` — зафиксированные группы и
  разбиение на пять фолдов для обучения.
- `outputs/validated_blend/training_report.json` — отчёт итогового обучения.
- `quality_core/` — реализация ансамбля, обработки данных и формирования
  результата.
- `third_party/` — локальные копии вспомогательного кода Qwen для расчёта
  эмбеддингов и обработки изображений. Рядом сохранены лицензии и метаданные
  исходных пакетов.

## Подготовка после клонирования

Матрица эмбеддингов и готовая модель хранятся через Git LFS. Перед запуском их
нужно загрузить:

```bash
git lfs install
git lfs pull
```

## Получение предсказаний

Среда выполнения указана в `metadata.json`:

```text
odsai/ecup26-quality-baseline:1.0
```

В каталоге `SHARED_MODELS_PATH` должны находиться следующие модели:

```text
Qwen/Qwen3-VL-Embedding-2B
Qwen/Qwen3.5-4B
```

Если переменная `SHARED_MODELS_PATH` не задана, используется каталог
`/shared_models`. В тестовом CSV обязательны столбцы `id`, `name`, `description`
и `category`. Рядом с CSV должен находиться каталог `images`:

```text
input/
├── test.csv
└── images/
```

Команда запуска:

```bash
python -u run.py \
  --test-data-path input/test.csv \
  --output-path output/submission.csv
```

Выходной файл содержит ровно два столбца: `id,result`. Значение `result` имеет
один из двух форматов:

```text
<комментарий>...<вердикт>бан
```

или

```text
<комментарий>...<вердикт>не бан
```

## Воспроизведение обучения

Для обучения нужен официальный файл `data/data.csv`. Точные эмбеддинги,
выровненные по его строкам, и зафиксированное разбиение по группам источников и
шаблонов уже включены в репозиторий:

```text
outputs/mixed.npy
outputs/source_template_stress_manifest_v2.npz
```

В манифесте нужно использовать массив `fold__seed_15485863`. Команда запуска:

```bash
python -u train_validated_blend.py \
  --data data/data.csv \
  --embeddings outputs/mixed.npy \
  --manifest outputs/source_template_stress_manifest_v2.npz \
  --fold-key fold__seed_15485863 \
  --output outputs/validated_blend/rebuilt.joblib \
  --report outputs/validated_blend/rebuilt_report.json
```

Для каждого обучаемого компонента и каждой категории скрипт строит ансамбль из
пяти моделей — по одной на каждый фолд. Средние значения компонентов, их
стандартные отклонения и оптимальные по F1 пороги рассчитываются только по
предсказаниям для строк, которые не участвовали в обучении соответствующей
модели.

## Модели и данные

Для мультимодальных эмбеддингов используется `Qwen/Qwen3-VL-Embedding-2B`, а
для пояснений при получении предсказаний — `Qwen/Qwen3.5-4B`. Обе модели
распространяются по лицензии Apache-2.0. Их размеры — 2B и 4B соответственно,
что соответствует ограничению задачи.

Для обучения не использовались сгенерированные метки, псевдоразметка или
синтетические примеры, проприетарные API или внешние размеченные данные.
